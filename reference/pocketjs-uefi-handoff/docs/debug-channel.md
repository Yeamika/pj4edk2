# PocketJSDebug 数据通道

本页说明默认页面的调试开关、PJB 提供的数据接口，以及 BSP 的连接责任。

> [!NOTE]
> 状态：开关、有界双向队列和 BSP 通知已实现，并完成宿主检查。尚未接入实体传输、DevTools 命令解析或源码断点调试。

## 默认行为

每次创建运行时，`PocketJSDebug` 都是 OFF。打开设置、读取启动参数、保存倒计时、选择默认启动项都不会开启调试。开关不写入
`BootSettings`；旧配置或自定义参数里的同名值也不会作为开启指令。

只有用户在设置里点击 `PocketJSDebug`，或用 Tab 聚焦该按钮后按 Enter，页面才发出
`SetDebugEnabled`。开关立即应用于本次运行，无需点击 Save，也不改变倒计时输入的 `*`。页面等待 `DebugConfigured`
返回实际状态，失败时显示错误边框并允许重试。

UEFI 和嵌套 loader 使用同一运行时的数据通道。子页面修改开关后，返回父页面仍显示当前实际状态；重新创建运行时恢复 OFF。 嵌入式
`replace_user` 只替换用户 context，因此保留运行时的调试状态。

## PJB 与 BSP 的边界

[`pocketjs-debug-channel`](../crates/debug-channel/src/lib.rs) 是独立的
`no_std + alloc` crate，只提供不透明字节队列。 Windows 演示和嵌入式 `PocketJs::debug_channel()`
使用同一实现。PJB 不创建串口、USB、网络设备、线程或监听端口，也不解释收到的数据。

建议 BSP 在收到 `BootServices::set_debug_enabled(true)` 通知后接通板级传输；收到 false
后停止收发并断开连接。 宿主先改变 PJB 数据门控，再通知 BSP。连接失败时关闭门控并请求 BSP 撤销可能的部分连接；断开失败时门控仍保持关闭。
桌面实现仅记录并打印通知，不自动开启网络连接。

物理连接可以由 BSP 持有，但队列只在拥有运行时的执行线程访问。中断或其他核先把数据放入 BSP 自己的队列，在 UI 帧边界转交；不能从设备回调重入
QuickJS。实际适配与错误回滚参见桌面分派（外部桌面参考工程，未纳入本仓库）。

## 数据接口

| 方法                      | 用途                                       |
| ------------------------- | ------------------------------------------ |
| `enabled()` / `session()` | 读取门控状态与当前连接令牌；关闭时没有令牌 |
| `set_enabled(bool)`       | 宿主处理用户选择；关闭会释放双向队列       |
| `send(session, bytes)`    | 调试适配器向 BSP 提交输出数据              |
| `take_outgoing(session)`  | BSP 取出一包待发送数据                     |
| `deliver(session, bytes)` | BSP 提交一包输入数据                       |
| `receive(session)`        | 调试适配器取出一包输入数据                 |

调用立即返回，不等待设备。队列保持 FIFO，按每次提交保留包边界；字节流传输的拆包、合包和协议帧由适配器负责。 默认每包最多 4096 字节，每个方向最多 8
包、总 payload 最多 16384 字节。调用方可用 `Limits` 配置更小的容量。 超限返回 `PacketTooLarge` 或
`QueueFull`，由调用方处理背压。

关闭会丢弃双向积压数据，并拒绝后续 I/O。重新开启生成新的 `Session`；前一连接的延迟回调使用旧令牌会收到 `StaleSession`。
该令牌只用于所属通道的本地连接代次，不是 EFI 句柄或跨 loader ABI。真实固件交接仍通过驻留服务和现有实例租约访问通道。

## 接入 DevTools

通道本身没有 JS 求值、暂停、节点查询或包更新命令。需要这些能力时，由宿主另行接入上游调试 shim 与协议解析器，验证请求后在当前实例的帧边界处理。
普通页面的 `svcSend` / `svcPoll`
仍属于应用宿主消息，不会隐式开启或连接调试通道。上游已有能力及限制见[用户层存储与调试](userspace.md)。

## 验证

通道检查覆盖默认关闭、双向不透明字节、FIFO、容量限制、关闭清空和旧连接拒绝。真实 QuickJS 页面检查覆盖显式点击、重复点击抑制、键盘开启、BSP
连接与断开失败，以及嵌套 loader 返回后的状态同步。十档 360p 至 1440p 视口分别验证物理坐标点击 OFF→ON→OFF。

这些检查未连接实体调试设备，也不代表远程调试器已经可用。
